# 开发指南

改这个插件之前看这一份就够了。下面的每个事实都对应代码，标了文件位置；与代码冲突时以代码为准。

## 0. 动手前

| 要命的是 | 做法 |
|---|---|
| profile `desktop` 用 `link:` junction 指向本仓库 | 改 `index.js`、`lib/` 下**宿主侧**代码，**必须重启 DSH** 才生效 |
| `lib/client.js` 是设置页前端，由宿主启动时读取 | 单改它：刷新页面即可 |
| 运行期数据在用户家目录，不在仓库里 | 调试别往 `~/.dsh/whale-pal/` 里写测试数据，用临时目录 |

验证只跑一条命令：

```bash
node scripts/verify.mjs
```

它做三步（[scripts/verify.mjs](scripts/verify.mjs)）：**语法**逐文件 `node --check` → **导入**真 `import` 一次 `index.js` 与人格内核，核对 `name` / `inject` / `apply` / `applyPersona` → **测试**把 `test/**/*.test.mjs` 与 `lib/persona/test/*.test.mjs` 一次性交给 `node --test`。

基线（2026-11-12）：语法 65 个文件、`inject` 五项、测试 909 条 / 59 个文件全过，Node 22 与 24 同数。

`npm test` 在 Windows 上不可靠（靠 shell 展开 glob），用 `verify`。`test/eval/run.mjs` 不是测试文件——模块一加载就 `main()` 并去读真库，`verify` 故意不收它。

## 1. 一次会话里发生什么

按时间顺序，每一环的入口都给了代码位置。

**启动（[index.js](index.js)）**

1. `resolveDataPaths()` 算出数据根 `~/.dsh/whale-pal/<profile>/`，顺带算出旧根与导入记录位置（[lib/paths.js](lib/paths.js)）。
2. `legacyStillLoaded()`：profile 里还挂着旧插件 `dsh-persona-framework` 就直接不启动——**不许双活**，理由在 [index.js:9-11](index.js#L9-L11)。
3. `runImport()`：旧状态只在第一次导。先存导入前快照 → 导 → 逐项核对 → 旧文件置只读。
4. `applyPersona()` 装配人格内核，拿回进程内 `api`。失败只降级，不 throw。
5. `registerSurface()` 挂设置页、`/whale` 命令、工具、模式段、进度段、锚定块。挂失败只记日志。

**每一轮对话**

系统提示是**五段按顺序拼接**的，`ORDER` 写死：

| 段 | ORDER | 内容 | 代码 |
|---|---|---|---|
| 人格内核 | 90 | 名字、底色、价值观、边界、说话风格 | [lib/persona/index.js](lib/persona/index.js) |
| 状态摘要 | 91 | 六行：记得 / 一直记着 / 答应过 / 未完成 / 上次 / 目录 | 同上，`renderStateSummary` |
| 模式 | 92 | 鲸鲸 / 助手，定人格表达与任务准确性的主次；事实、校验、安全不参与排序 | [lib/mode.js](lib/mode.js) `modeText` |
| 六阶段进度 | 93 | 拆解 → 补全 → 自检 → 对照 → 串联 → 交付，当前阶段与待确认项 | [lib/progress.js](lib/progress.js) |
| 锚定块 | 94 | 上下文档案的热索引，≤300 字，每次现算**不落盘** | [lib/ctx/inject.js](lib/ctx/inject.js) |

90–93 是「稳定前缀」，94 是它后面的热索引，只在有新档案时才变。**改顺序等于打掉前缀缓存**，见第 5 节。

**人格开关（2026-11-21）**：设置页「人格开关」关掉后，90–93 四段一律返回空串（不是注销，注册还在，拨回来立刻有字），94 锚定块照旧。转录、评估、更新、落盘、上下文压缩全都不受影响——人格和记忆是两条线，这条开关只切提示词。开关存在 `config.json` 的 `persona.enabled`，缺省/写坏都按开着算（老配置升级后行为不变）。

**轮末（`session/event` 派发的 `turn/end`）**

> 钩子一律声明成 `ctx.on('session/event', …)`，`turn/end` 只是其中一种事件。直接写 `ctx.on('turn/end')` **永远不响**——这条踩过，见 [lib/ctx/host-bridge.js:1041-1050](lib/ctx/host-bridge.js#L1041-L1050)。

- 人格评估：`important` 档只在「双方都说过话、转录 ≥80 字」时发动一次独立小模型调用，抽出事实 / 偏好 / 事件 / 未完成 + 承诺，写进 `state.json`（[lib/persona/lib/assessor.js](lib/persona/lib/assessor.js)）。
- 上下文档案：**不落盘**，只把「该写什么」累积进投影状态。

**压缩时（`compaction/summary`）**

宿主每次压缩都发这个事件，投影把它折成「待写档案」队列——**只折，不写盘**。**每轮收尾**时 `autoArchive` 消费队列：摘要落成 `_上下文/压缩档案/<blockId>.md`，按 seq 回捞原文，重算 `索引.md`（[lib/ctx/host-bridge.js:1153-1157](lib/ctx/host-bridge.js#L1153-L1157)）。`/whale ctx sync` 与工具的 `sync` 是同一条路的**手动入口**，不是唯一入口。投影里写盘是硬约束，见第 5 节。

**压完仍超**

插件开一个新会话接着干，旧会话同时停掉自动压缩（[lib/ctx/switch.js](lib/ctx/switch.js)）。这一条**只在测试里验过**，真机没自然触发过。

## 3. 五个子系统的手册

### 3.1 人格内核 · `lib/persona/`

**干什么**：旁路。它从 `session/event` 自己攒一份转录，到 `turn/end` 用一次独立的小模型调用判断「这轮值不值得记」，落成 `state.json`。注入只有两段：`renderKernel(config)` 随配置变（身份与硬规则，order 90），`renderStateSummary(state, config, {query})` 随状态和这轮用户原话变（六行摘要，order 91）。**没有 pre-step 注入**。

| 文件 | 职责 |
|---|---|
| `index.js` | 装配：读配置/状态 → 注入两段 → 订阅事件 → 调度评估 → 写盘闸 |
| `lib/config.js` | 配置归一化、默认值、字数上限、**名字兜底 `effectiveBotName`** |
| `lib/transcript.js` | 会话事件 → 「谁说了什么」的转录缓冲，24 条 / 4000 字 |
| `lib/assessor.js` | 评估的 system 提示、抠 JSON、跑一次流式调用（超时 30s、`maxTokens: 600`） |
| `lib/updater.js` | 把评估结果落成状态变化，产出可审计的 `changes`（不改入参） |
| `lib/memory.js` | 记忆规则：去重、重要度、淡忘、晋升、编号 |
| `lib/recall.js` | 召回与四档分级 |
| `lib/retrieve.js` | 「编号 → 原文」取回与目录行 |
| `lib/prompt/render.js` | 内核逐行渲染 + 六行摘要 + 三段字数账 |
| `lib/sanitize.js` · `lib/validate.js` | 注入安全零件 · 设置页字段规则表（标红的唯一来源） |
| `lib/state/schema.js` · `lib/state/store.js` | 状态形状与硬上限 · 路径/原子写/快照/审计/串行锁 |

**一轮的链路**：`user/message` 到达 → 取最后一条原话当 query，变了才重算摘要 → `turn/end` 判 `hasSubstance`（≥2 条、一问一答、尾部 4 条合计 ≥80 字）→ 挂到串行链 `assessChain`（同一时刻只有一个评估）→ 只送增量 `from = assessed - 2` → `applyAssessment` 写记忆、做完的 `openTopics` 结账、四类一起淡化、晋升、承诺增改 → `changes` 非空才落盘（`setState` = 快照 + 写者闸 + 审计 + 原子写）。

**关键数**（[lib/persona/lib/memory.js](lib/persona/lib/memory.js)、[schema.js](lib/persona/lib/state/schema.js)）：

- 上限：事实 200 · 偏好 60 · 事件 60 · 未完成 30 · 长期 40 · 承诺 20
- 淡忘 `rate = 0.02`/轮，低于 `FADE_FLOOR = 0.12` 不进注入；列表 > `cap × 0.8` 时从尾部清到 `cap × 0.6`
- 重复一次 `hits + 1`、`HIT_GAIN = +0.08`；`hits ≥ 3` 晋升长期层，晋升后短池里删掉不留两份
- 注入配额：记得 4 · 一直记着 3 · 答应过 1 · 未完成 2 · 目录 5 行（整行 ≤20 字）· 摘要总长 600

**改哪个**：

| 想改 | 动 | 跑 |
|---|---|---|
| 每轮记几条、多长、算不算有实质 | `assessor.js` 的 `MAX_ITEMS`/`MAX_TEXT`/`ASSESSOR_SYSTEM`、`transcript.js` 的 `size >= 80` | `assessor` `transcript` `memory` |
| 加一种记忆类型 | `MEMORY_KINDS`、`BASE_SALIENCE`、`normalizeLong` 白名单、`CAPS`、`updater` 的 `memoryCaps`、`assessor` 的键列表、`render` 的 kinds | `memory` `updater` `longmemory` `render` `retrieve` |
| 改注入文案 | `render.js` 的 `kernelLines()` / `renderStateSummary()` / `DROP_ORDER` | `render`（有「三段之和 = 真实字数」断言） |
| 改衰减 | `FADE_FLOOR`、`HIT_GAIN`、`scoreEntry` 的 `0.4`/`80`、`rate`、`PROMOTE_HITS`、`recall.js` 的 `TIER_THRESHOLD` | `memory` `recall` `longmemory` |
| 改名与兜底 | `DEFAULTS`、`effectiveBotName`（`'鲸鲸'` 就在这）、`validate.js` 的 `max`/`hint` | `config`（会断言默认名是空的）、`validate`、`render` |

**坑**：

- `state.json` / `config.json` **不走** `lib/atomic.js` 那套 `.bak-`，它们归人格内核管；回滚点是 `snapshots/`，每轮存一份、留 20 份。
- 已存在的 `state.json` 里 `selfName.current` 不会因为改配置而变——`normalizeState` 只补缺失字段。
- 转录只吞 `text` 块，带 `interrupted` 的 assistant 消息整条丢。
- 子代理的会话不参与人格状态（`header.origin === 'subagent'` 直接跳过）。
- 会话缓冲最多 32 份，超出按**插入序**删最老的，不是 LRU。
- `audit.jsonl` 只追加不清理，所以 `recordAudit` **写前判轮转**：到 4 MB 就把旧内容挪进 `audit.jsonl.1` 再写。序号存在 `state.audit.lastSeq` 里，轮转不会把序号打回 1；台账扫 audit 时两档一起读（见 3.3）。

### 3.2 上下文压缩档案 · `lib/ctx/`

**干什么**：宿主每次压缩发 `compaction/summary`，投影把它折成「待写档案」队列（只折不写）；每轮收尾 `autoArchive` 落盘成卡片 + 原文 + 索引。模型常驻看到的只是锚定块（≤300 字，每次现算，不落盘）。另一条线是 `whale_ctx` 工具与 `/whale ctx` 命令：检索、读回、补条目、按批查、整批回滚、拼深链（`open`）。

自动压缩主管道：到点量已用量 → 先修剪 → 不行再借宿主 `/compact` 压一次 → 下一轮复检 → 判成「压了没用」就停掉自动压缩、只留提醒并自己开新会话。

触发点两个系数可以从配置来：`config.compaction.ratio`（默认 0.16）、`config.compaction.floorMargin`（默认 0.04）。压缩器每轮现取，改 `config.json` 下一轮就生效，不用重启；只收 (0, 0.8) 内的数字，写 0、写负数、写字符串都回默认值，不让坏配置把压缩变成「每轮都压」或「永不压」。

| 文件 | 职责 |
|---|---|
| `store.js` | **本目录唯一碰盘层**：路径、卡片读写、队列、回收站、原文 |
| `watch.js` | 投影：把压缩事件折成待写队列（`apply` 不许写盘） |
| `archive.js` · `index3.js` · `entries.js` | 卡片五格解析与渲染 · 索引八列 · 条目抽取合并 |
| `inject.js` | 锚定块：选行、裁到 300 字、算哈希（**不许带日期**） |
| `raw.js` · `original.js` | 原文拼装与截断 · seq → 卡片 → 原文那一节（只读） |
| `search.js` · `rebuild.js` · `batch.js` | 按词自查（上限 3 条）· 从卡片重装索引 · 批次号与摘批 |
| `threshold.js` · `trigger.js` · `source.js` | 三档阈值 · 触发点与提醒点 · native/occupied/none 三态来源 |
| `compact.js` · `compact-cmd.js` · `switch.js` | 主管道 · 借 `/compact` 压一次 · 压不动时开新会话 |
| `host-bridge.js` | 接线：工具、命令、投影、提醒、自动落盘、换会话 |

**改哪个**：

| 想改 | 动 | 跑 |
|---|---|---|
| 卡片格式 | `archive.js` 的解析与渲染、`store.js` 的 `cardOf`/文件名，索引跟着变再动 `index3.js` `rebuild.js` | `ctx-archive` `ctx-index3` `ctx-rebuild` `ctx-store` |
| 三档阈值 | `threshold.js` 的 `LIMITS`/`REMIND_MARGIN`、`host-bridge.js` 的提醒文案；同时改自动压缩点再动 `trigger.js` | `ctx-threshold` `ctx-trigger` `ctx-surface` |
| 检索逻辑 | `search.js` 的命中范围与上限、`index3.js` 的解析 | `ctx-search` `ctx-index3` `ctx-rebuild` `ctx-surface` |
| 注入的锚定块 | `inject.js` 的选行/裁剪/哈希与 4 个上限常量、`lib/host.js` 里 `ANCHOR_SECTION` 的挂法 | `ctx-inject` `ctx-surface` |
| 整批回滚 | `batch.js`、`store.js` 的 `trashBatch`、`host-bridge.js` 的 `ctxRollback` | `ctx-batch` `ctx-store` `ctx-surface` |

**坑**（这一节是全仓踩坑最密的地方）：

- **投影的 `apply` 绝不写盘**。写了就把所有档案重写、mtime 全变、前缀缓存全废。
- **不要在 `export const inject` 里声明 `compaction`**：任一依赖解析不到会把**整个插件**置为 INACTIVE。用子 fiber 探针。
- 取可选服务要「先直接取、再走 `ctx.get`」——没声明 inject 的服务直接属性访问会抛，`if (ctx.x && …)` 这个守卫自己就抛。
- 投影注册失败不能静默跳过，要记 warning 并走 `ctx.inject` 回调；否则日志不响、健康检查全绿、压缩白压。
- **先压缩、后落盘**。反了这一轮的摘要要等下次压缩才进库。
- 真机信封只有 `time` 和 `seq`，**没有 `at`**；早期读 `event.at` 恒为空串，卡片全被判不合法（716 条测试都没照出来）。
- 锚定块里不许出现任何日期时间，否则哈希每次都变。
- 已落过的 `blockId#gen` 必须跳过，否则重放会给同一张卡换号（`C001` → `C002`）。
- 内容一样就一个字节不动——**mtime 是前缀缓存的命根子**；先写 `.tmp-<pid>-<time>` 再 rename。
- 关键词不能加「出现 ≥2 次」这类收紧条件，摘要一薄就凑不够，整张卡写不进去。
- 原文只供后期检索，**绝不进上下文**；被宿主 prune 掉的 seq 必须写在最前面，不许装作整份都齐。
- 档案里 200–2000 字、关键词 3–5 个的校验只约束「按模板写摘要」那一路；宿主的落档路给多长存多长。
- `commands.execute` 返回 `{commandId, result: {kind, text}}`，直接读 `.kind` 永远 undefined；`agent.status` 把 maintenance 也报成 `idle`，用它判忙会误放行。
- `controller.prompt` 第二参必须给 AbortSignal；交接条第一句必须写明「不是用户本人发的话」。

### 3.3 台账 · `lib/ledger/`

**干什么**：四本账写成用户笔记库里的 `台账/*.md`，裸 Markdown 表格，一行一条，**只追加**。过期承诺**不自动扫**（2026-11-21 把节律那半边整块砍了：日/周/月提醒、六小时定时器、启动扫描、`turn/end` 投递、第五本 `待提醒` 账、`rhythm-state.json` 与 `ledger-state.json` 全删）。要看就说一声 `/whale ledger scan`（或工具的 `action=scan`）：扫一次、写一次、当场把新捞到的列出来。

| 文件 | 职责 |
|---|---|
| `ledger/table.js` · `ledger/books.js` | 表格行渲染与解析（唯一改写口 `replaceRow`）· 四本账的列定义与行操作 |
| `ledger/event.js` · `ledger/lapse.js` | 事件行与「隔天才催补」· audit 的 lapse → 待交接 |
| `ledger/store.js` | **本目录唯一 `node:fs`**：落盘、写后读回、audit 只读扫描 |
| `ledger/host-bridge.js` | 接线：`createLedger` 给的读写口、按需扫 audit |
| `mode.js` | 按 cwd 定模式（见本节末） |
| `progress.js` · `token.js` | 六阶段状态机 · 确认口令的解析 |
| `persona-card.js` | 人格卡原文 ↔ 十一项，认不出的进 `rest` 不丢字 |

**四本账**：

| 账本 | 列 | 能事后补的 |
|---|---|---|
| 事件 | 时间 \| 类型 \| 发生了什么 \| 当时的判断 \| 结果 \| 教训 | 判断 / 结果 / 教训 |
| 偏离 | 场景 \| 偏离 \| 原因 \| 改法 | 原因 / 改法 |
| 异议 | 时间 \| 议题 \| 我的看法 \| 你的看法 \| 处理 | 处理 |
| 待交接 | 时间 \| 键 \| 答应过的事 \| 状态 | 状态：待处理 → 已结 / 已忽略 |

事件类型只有四种：任务 / 纠正 / 偏好 / 观察。

**模式**：只有 `assistant`（默认）和 `whale` 两种。判定只有一处——`resolveMode({ config, cwd })`：cwd 在 `config.whaleWorkspaces` 名单里就是鲸鲸，其余助手。目录比较会归一斜杠与尾斜杠、Windows 下转小写，**子目录不算同一目录**，空 cwd 一律助手。`/whale mode|bind|unbind` 改的是**目录绑定**，不是当前会话的开关；改完 fire-and-forget 把工作区名加上或剥掉 `【鲸鲸】` 前缀，改名失败只记日志、不回滚绑定。**任何模式都不放松**：门禁与确认口令按字面判、事实不许编造。

**改哪个**：

| 想改 | 动 | 跑 |
|---|---|---|
| 加一列台账 | `books.js` 对应账本的 `columns`/`placeholders`/`keyOf`，事件还得改 `event.js` 的 `FILL_COLUMNS` | `ledger-books` `ledger-store` `ledger-surface` |
| 改六阶段确认规则 | `token.js` 的 `parseConfirm`、`progress.js` 的阶段入口；改阶段数或名字还要动 `STAGES`/`LAST_STAGE` 与七种渲染写法 | `token` `progress` |

**坑**：

- **补齐只能换「待补」那三格**，空值不算补齐、整条拒绝。这是防「补齐变成悄悄改历史」的唯一通路。
- 同一幂等键已在账上就直接跳过，**一个字节都不写**。
- 已「已忽略」的行不许事后改成「已结」。
- 加列时必须同步 `host-bridge.js` 里几处**写死的列下标**（交接列表、状态列 3）。在状态列前插列要一起改；`偏离` 的幂等键是整行拼接，加列会改变所有新行的键。
- **扫描只在被叫到时跑**：`createLedger` 不挂定时器、不挂会话钩子，所以「没人看的时候台账自己长」这件事不会再发生。想加自动扫描前先想清楚出口在哪——2026-11-05 到 11-21 那段就是反例：报了半个月一句没投出去，待交接却堆了 685 行。
- 每次从 0 扫，靠待交接的幂等键去重；有 200 条地板，避免把历史 lapsed 一次灌进待交接。
- 扫 audit 时**当前文件和 `audit.jsonl.1` 一起读**（`readAuditRecords`）。只读当前文件的话，轮转那一刻「已写但还没被扫到」的 lapsed 事件会静默丢掉——旧档走了，当前文件看不着。
- 时区偏移别用 `Number.isFinite(Number(value))` 判「没传」——`Number(null) === 0`，会把没传当成 UTC。
- 只有 `lib/ledger/store.js` 能碰盘；纯模块不许出现 `Date.now` / `process.env`，`test/ledger-store.test.mjs` 会扫 import 锁死。
- 进度点的七种渲染写法**改一个字都要先问人**，`test/progress.test.mjs` 逐字锁着。

| 改备份与回滚 | `atomic.js` 的保留数/修剪/`writeWithBackup`/`writerGate`、`backup.js`、`host.js` 的 `runRollback`/`rollbackRoots` | `atomic` `backup` `surface` |

**坑**：

- 写盘顺序固定：**先 `.bak` → 写同类目 `.tmp` → rename → 逐字读回**。备份拿不到或字节校验不过就**不动原文件**；读回不一致才用备份盖回，并如实报 `rolledBack`。
- `state.json` / `config.json` 不走 `atomic.js`；`atomic.js` 自己也不 import 人格内核的写函数。
- 跨盘、同卷都**不许靠 rename 搬库**，一律「复制 + 逐字校验 + 最后删源」。
- 设置写入是事务：**迁移 → 写状态 → 写配置**，配置落盘才是提交点；状态失败撤迁移副本，配置失败把状态退回原样。
- 超长一律拒收，**不替人截断**；路径更不能截断，截断后就是另一个目录。空白照收，清空是合法改动。
- 笔记库路径必须已存在、是目录、可写，**插件不替人建库**；相对路径一律拒。
- 路由里任何未捕获异常都会被 catch 成 `400 body-not-json`——新 handler 抛错时错误码会说谎，别靠它区分 500。
- 加新服务时走 `service(ctx, key)` 的**可选注入**，不要写进 `export const inject`：任一依赖解析不到，整个插件置 INACTIVE。
- 客户端路由只能写文档相对路径（GUI 带 `<base href="./">`），写绝对路径会逃出子路径。
- **前端与内核的长度口径有落差**：`name` 允许 40 字但内核只留 10 字；`selfName`/`title` 允许 40 但 state 截到 20。超长不会被设置层拒，会被内核静默裁短。
- 界面文案一律从 `COPY` 取；禁词表 `BANNED` 由测试扫描。
- 回执只让失败说话，成功一个字不说。

## 5. 不许破的约束

改任何代码前先过一遍这一节，都是踩过才写下的。

1. **写权只有一处**。所有落盘都走人格内核返回的 `api.setConfig` / `api.setState`，不额外开写者（[lib/host.js:13-14](lib/host.js#L13-L14)）。
2. **投影的 `apply` 里绝对不许写盘**。会话每次加载都会从事件日志重放一遍投影，`apply` 里写盘等于每开一次会话就把所有历史档案重写一遍，mtime 全变、前缀缓存全废。正确做法是把「该写什么」累积进状态，交给只发生一次的时机消费（[lib/ctx/watch.js](lib/ctx/watch.js)）。
3. **台账只追加**。结论过期不改老行，另起一条「纠正」；「当时怎么判断」那列不美化（[lib/ledger/books.js](lib/ledger/books.js)）。
4. **不许双活**。旧插件还在 profile 里就不启动（[index.js:84-87](index.js#L84-L87)）。
5. **人格内核失败只降级不 throw**。宿主装配抛错会把整个外壳挡在门外，人格只是附加能力，不该有否决权（[lib/persona/index.js:11-13](lib/persona/index.js#L11-L13)）。
6. **确认口令按字面判**。「对 / 好 / 嗯」在任何模式下都不算确认，改动涉及门禁时别放宽。
7. **解析失败不许覆盖原文件**。配置写坏了回默认值继续跑，但不要拿默认值把用户的原文件盖掉。
8. **默认通用，不默认本机**。窗口大小、路径、平台都不许当场拍死，留配置项或按运行期实测取值。
9. **生产代码里别用 `fs.cpSync`**。Node 22 + Windows 上 `cpSync(..., {recursive: true})` 会直接把进程打死（`3221226505` / `0xC0000409`），catch 不到；Node 24 正常。`lib/atomic.js` 因此自己写了 `copyTree`。`scripts/` 与 `test/eval/` 里还有几处仍在用，它们不在生产路径上，但改成 `copyTree` 更稳。
10. **凡用户可见的文案都从 [lib/copy.js](lib/copy.js) 出**，`BANNED` 里有禁词表，`test/contract.test.mjs` 会查。
11. **命令里的确认门现在是子串判断**：[lib/import/command.js:74](lib/import/command.js#L74) 用 `said.includes('确认')`，所以 `/whale import rollback 不确认` 也会真回滚。新写门禁别照抄这个写法，要按字面判且按字面排除否定词。

## 6. 验证与发布

```bash
node scripts/verify.mjs                       # 交付前必跑：语法 + 导入 + 1022 条测试（64 个文件）
node test/eval/run.mjs --data-dir <临时目录>   # 评测集；它会读真库，别让它跑在活数据上
```

发版（npm 账号开了 2FA，非交互发布会 `E403`）：

```bash
npm version patch               # 或 minor / major
git push --follow-tags
npm publish --otp=<六位码>       # 没 OTP 就换成带 bypass-2fa 的 Granular Access Token
```

npm 11 是**暂存式发布**：`publish` 当场返回 `202`，约两分钟后真版本才出现并成为 `latest`。别看到 202 就以为失败。

GitHub 侧：推 tag 会触发 CI（Node 22 + 24 矩阵），发布 release 时附上变更说明。

**`engines.dsh` 不是装饰。** 宿主在装/激活前用 `semver.satisfies(运行时版本, engines.dsh, { includePrerelease: true })` 判（`@deepseek-ai/dsh-app-boot` 的 `evaluatePluginCompatibility`），不满足就**直接不激活**，不会带着缺接口的状态硬跑。本包声明 `>=0.2.2-rc.3`：下界是实机验过的最低版本，上界故意不写——`^` 那种写法会让宿主小版本一升插件就静默停用。升级 DSH 之后先跑 verify、再真机过一遍主要功能；确认没踩到改过的接口，就不用动它，踩到了先修代码再抬下界。
